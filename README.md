# 基于视觉反馈的钢球位置串级控制系统

> 以 TI MSPM0G3507 为主控、K230 视觉模块为传感器的钢球位置闭环控制系统。
> K230 端运行自训练的 YOLOv5nu 单类检测模型（量化部署为 kmodel），实时解算钢球在轨道上的偏差与速度；
> 主控以 200 Hz 串级 PID 驱动舵机调整轨道倾角，实现钢球的定点往返、定点保持与抗扰动保持，
> 并完成竞赛第 3～6 问的全部任务与交互界面。

## 系统架构

```
K230：YOLOv5nu(kmodel) 检测 → 框中心像素 → 两点标定 → 位置 / 速度 → 5 字节帧
      ──UART2 / 115200──▶ 帧解析 ──▶ 位置环 PID ──▶ 加速度限幅 ──▶ 速度环 PID ──▶ 舵机 PWM
      ──▶ 轨道倾角 ──▶ 钢球位置 / 速度 ──▶（回到 K230 视觉，闭环）
      ▲
      └─ 5 ms 控制周期（200 Hz）· 1 ms 系统节拍：计时 + 按键扫描
```

软件按三层划分，模块之间只通过头文件接口耦合：

- **驱动层**：逐飞库提供的时钟、GPIO、PWM、UART、PIT、OLED 等驱动；
- **模块层**：`pid`（通用 PID）、`car_uart`（视觉协议）、`duoji`（舵机运动规划）、
  `key`（按键状态机）、`stopwatch`（毫秒计时）、`OLED`（显示）；
- **应用层**：`subject`（题目状态机与目标生成）、`main`（中断与任务调度）。

## 视觉端：从检测模型到位置输出

视觉链路覆盖训练 → 导出 → 量化 → 校验 → 板端推理，脚本全部位于 `1_K230/`：

| 环节 | 脚本 | 关键设置 |
| --- | --- | --- |
| 训练 | `Ctrain.py` | Ultralytics YOLOv5nu，单类别 `ball`，224×224，150 epochs，batch 16，cos_lr，mosaic + HSV + 缩放增强 |
| 导出 | `export_onnx.py` | `best.pt` → ONNX：opset 11、固定 224×224、simplify、batch = 1、**不含 NMS**（后处理放在板端） |
| 量化 | `YOLO-KModel-Converter-Portable-Slim-Win` | 选 ONNX + YOLOv5 + detect + 224×224，配合实景校准集（≥ 20 张）做 PTQ，输出 `.kmodel` |
| 校验 | `verify.py` | 用 nncase Simulator 与 onnxruntime 分别推理同一张图，逐路输出计算余弦相似度，> 0.99 视为合格 |
| 推理 | `YOLOV5改进.py`（标定_串口） | K230 CanMV：检测 → 取最高分框 → 两点标定 → 位置/速度 → 串口发送 |
| 图传 | `rtsp_图传.py` | WiFi + RTSP（H.264，512×288，1500 kbps，15 fps），远程观察画面，方便调机与标定 |

**检测与后处理**：模型只做单类别钢球检测，取置信度最高的框，用框中心横坐标 `cx` 作为钢球像素位置；
置信度阈值 0.5、NMS 0.45、最多保留 3 个框，NMS 在板端执行以减小模型体积。

**两点标定代替固定比例**：把钢球放在轨道 0 cm 与 +5 cm 处各按一次键，程序用两次 `cx` 的差值反算
`scale = 5.0 / (cx_5cm − cx_0cm)` 与 `offset`，写入 `/data/calib.json` 掉电保存；
位置按 `pos = (cx − offset) × scale` 换算成厘米。这样更换机位、镜头或轨道高度后重新标定即可，
不必改代码、不必重新训练。

**速度解算与保护**：用 5 帧滑动窗口对位置做差分测速（`Δt` 由 `ticks_ms` 计算），
结果限幅 ±50 cm/s 防止跳变；一旦丢失目标，重置窗口并强制速度为 0，避免把"看不见"误判成"高速运动"。
最终偏差放大 100 倍取整、速度按 int8 饱和截断，封装成与主控约定的 5 字节帧发出。

**板端交互**：长按 1 s 进入/退出标定模式，短按依次采样 0 cm 与 +5 cm 两点；
屏幕 OSD 实时显示 FPS、位置、速度与 `cx`，标定过程有明确提示，现场无需连接电脑。

**精度要点**：量化后精度主要取决于校准图片是否覆盖真实场景（光照、背景、球位），
因此校准集取自实际轨道画面；同时保证训练、导出、量化、板端推理四处的输入尺寸与颜色顺序一致（RGB、224×224）。

## 主控核心技术

**1. 视觉数据链路：中断接收 + 环形缓冲 + 帧状态机**
串口以中断方式把字节写入 256 字节环形缓冲区，主循环侧的解析器按
`0xAA → 偏差高字节 → 偏差低字节 → 速度 → 异或校验` 的状态机逐字节推进，
校验通过才更新数据，无效帧自动丢弃。逐字节重同步保证了丢包、粘包场景下链路不崩溃；
同时保留最近一帧原始字节，便于现场排障。

**2. 串级 PID：位置外环 + 速度内环**
外环把位置误差换算为期望速度，内环把速度误差换算为舵机 PWM 偏移。
相比单环控制，串级结构把"位置"与"速度"解耦，抗扰动能力与稳定性明显提升，
是本题"钢球在运动车体上保持位置"的关键。

**3. 工程化的 PID 实现（`pid.c`）**
积分限幅抗饱和；微分作用改为**对测量值微分**并叠加一阶低通（α = 0.3），
避免目标值阶跃造成的微分冲击和视觉噪声放大；输出统一限幅，便于按题目切换量程。

**4. 平顺性与安全性处理**
外环输出增加**加速度限幅**（限制目标速度的每周期变化量），抑制钢球启停时的冲击与超调；
速度误差进入死区时清零积分并输出 0，消除稳态抖动；
当偏差或速度超出合理范围（|偏差| > 1500 或 |速度| > 100）时判定为视觉异常，
立即重置 PID 并使舵机回中，防止失控。

**5. 题目状态机（`subject.c`）**
第 3 问用显式状态机 `IDLE → GO_POS5 → WAIT_POS5 → GO_NEG5 → WAIT_NEG5 → DONE` 描述
"到 +5 cm → 稳定 → 到 −5 cm → 保持"的全过程，状态迁移同时判断位置阈值与速度阈值，
避免仅凭位置判定造成的误触发；第 4/5/6 问复用同一套控制回路，只切换目标生成方式。

**6. 参数集与人机交互**
`param_sets.h` 用参数表存放两套 PID 与限幅参数（静止折返 / 车体运动），按键即可切换题目，
无需重新编译；4 行 OLED 实时显示题号、状态、速度、目标与计时；
按键模块为四状态（空闲 / 按下消抖 / 按住 / 抬起消抖）状态机，支持短按与长按，
在 1 ms 节拍下扫描，无阻塞延时。

**7. 实时性设计**
两级定时中断：1 ms 节拍负责系统计时与按键扫描，5 ms 节拍负责串口取数与控制运算，
控制周期 5 ms（200 Hz）；通过中断优先级（控制中断 2、轮询中断 1）保证控制节拍不被通信阻塞。

## 构建与烧录

**主控端**

1. 使用 Keil MDK 5.37 打开
   `1_26h1_pid_subject3_6_jishi_cans_finally/project/mdk/SeekFree_MSPM0G3507_Device_Library.uvprojx`；
2. Rebuild（工程已包含全部依赖库，无需额外配置路径）；
3. 通过 J-Link / DAP 下载到 MSPM0G3507，复位运行；
4. 上电后 OLED 显示题号，短按 K2 切换第 3～6 问，短按 K1 锁定并启动；
   第 6 问先用 K2/K3 调整目标位置，K1 确认后启动，K3 可随时停止计时。

**视觉端**

1. `Ctrain.py` 基于 `yolov5nu.pt` 与 `ball.yaml` 训练，得到 `best.pt`；
2. `export_onnx.py` 导出 `best.onnx`（固定 224×224、opset 11）；
3. 运行 `YOLO-KModel-Converter-Portable-Slim-Win.exe`：选择 ONNX 模型、YOLOv5、detect、224×224，
   指定实景校准图片目录，量化选项先用 `0`，生成 `best.kmodel`；
4. `verify.py` 对比 ONNX 与 kmodel 的推理输出（输入尺寸需与模型一致），相似度达标后上线；
5. 把 `.kmodel` 与 `calib.json` 放到 K230 的 `/data/` 下，运行 `YOLOV5改进.py`；
   首次使用长按 1 s 进入标定，短按依次标记 0 cm 与 +5 cm。

视觉端通过 UART2（PA21/PA22，115200 8N1）按上述 5 字节协议与主控通信。
